# Technical learnings

Hetzner deployment (2026-10-04): Level 1 hosting supports FTPS on port 21 without requiring SSH shell access. Use `FTP_TLS` with a verified SSL context and call `prot_p()` to encrypt data transfers as well as login. The main account sees `/public_html/transcribe`; the dedicated additional account starts inside `public_html`, so its correct deployment target is `/transcribe`. Confirm the target by comparing its `index.html` bytes with the live HTTPS response. Upload files under temporary names, rename each into place, and publish `index.html` last; keep old assets and existing server files. Browser FFmpeg also needs Apache COOP/COEP headers in the production build, since Vite's development headers do not configure the hosted server. Sources: [Hetzner FTP access](https://docs.hetzner.com/managed/administration-on-konsoleh/access-details/ftp-sftp/), [Python FTP TLS](https://docs.python.org/3/library/ftplib.html#ftplib.FTP_TLS).

Model catalog refresh (2026-10-04): OpenAI recommends `gpt-transcribe` for ordinary file transcription and `gpt-6-astra` for maximum text-model capability, with `gpt-6.1-sol` and `gpt-6-luna` providing balanced and budget alternatives. GPT-6 supports Chat Completions for this app's text-only transformation requests, so no endpoint or SDK migration is needed; omit `temperature` because reasoning-enabled GPT-6 requests reject sampling parameters. OpenAI transcription requests should use the default JSON response rather than Whisper-specific `verbose_json`; the queue only consumes `text`. Groq's generally available production choices remain `whisper-large-v3` for transcription accuracy and `openai/gpt-oss-120b` for text quality. Catalog order supplies defaults without persisting them as explicit choices; `getStoredModel` preserves valid saved choices and falls back for missing or obsolete values. Sources: [OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-6 migration](https://developers.openai.com/api/docs/guides/latest-model), [OpenAI models](https://developers.openai.com/api/docs/models), [Groq models](https://console.groq.com/docs/models), [Groq transcription](https://console.groq.com/docs/speech-to-text).

Google provider integration (2026-10-04): `gemini-3.5-transcribe` uses the Gemini Interactions API with an audio Files API URI, rather than an OpenAI-compatible transcription endpoint. The official GenAI JavaScript SDK accepts browser `File`/`Blob` uploads and derives `output_text` from the response steps. Wait for uploaded files to become ACTIVE, delete them in `finally` on success or failure, and report cleanup failures without discarding the transcript; Google expires files after 48 hours. Set `store: false` for stateless interactions. Verbatim transcription is the default and allows one hour per request (30 minutes with diarization or word timestamps); enforce duration independently of byte size, leave a margin for MP3 frame boundaries, and retain overlap for stitching. Snapshot provider settings per job so changing providers cannot bypass the limits used during splitting. Gemini 3.8 Flash and 3.5 Flash-Lite support text transformations with a separate system instruction. Sources: [transcription](https://ai.google.dev/gemini-api/docs/transcribe), [Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview), [Files API](https://ai.google.dev/gemini-api/docs/files), [models](https://ai.google.dev/gemini-api/docs/models).

Live transcript formatting (2026-10-04): Capture provider annotations during the initial request and keep normalized cues separately from plain text. Gemini 3.5 Transcribe combines `mode: {type: "verbatim", diarization_mode: "speaker", timestamp_granularities: ["word"]}` and returns `word_info` annotations in model-output text; requesting these features reduces its audio limit to 30 minutes, so use a 1790-second split ceiling. Groq Whisper and OpenAI `whisper-1` use `verbose_json` with word/segment granularities; OpenAI ordinary transcribe models do not expose those timestamps, while `gpt-4o-transcribe-diarize` requires `diarized_json` and `chunking_strategy: "auto"`. OpenAI SDK 7 provides the corresponding request/response types. Track each chunk's absolute offset and ownership interval to remove overlapping word cues once; use contiguous cuts for segment-only diarization, and namespace speaker labels by audio part because independent requests cannot establish identical voices. Reject incomplete annotation sets as a formatting source instead of dropping speech. Store cues with recent transcripts, but evict older entries or omit annotations from an oversized cached entry when localStorage fills. Display/export switches operate on retained data and never call a provider. Sources: [Google transcription](https://ai.google.dev/gemini-api/docs/transcribe), [Groq transcription](https://console.groq.com/docs/speech-to-text), [OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text).
