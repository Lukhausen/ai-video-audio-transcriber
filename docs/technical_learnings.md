# Technical learnings

On the deployed mobile retry path, the saved chunk count skipped FFmpeg after a provider interruption. The cached chunks were already MP3, which made upload size alone insufficient to show whether the encoder reran. Verify the FFmpeg stream mapping as well as the request bytes. Re-encode the original under the same Web Lock used by the provider worker. Save replacement chunks and the retry receipt in one IndexedDB transaction so a queued worker can only submit newly prepared audio, and keep the completed prefix only while its stored chunk boundaries match.

The mobile Google report in issue #1 showed 0/2 after successful audio preparation. A synthetic 48:42 M4A reproduced the exact two-part state on the live build. Stopping Chrome's service worker during the first interaction released its Web Lock while the page kept waiting on the message port. Observe the lock while visible and reacquire it through the saved-request guard when the worker disappears. The receipt prevents resending an ambiguous request automatically. Use the bundled ffprobe to read duration and avoid false failure messages from a zero-frame FFmpeg run. In Chrome the bundled core returned -1 even though it wrote a valid 60.084-second duration, so validate the report as well as the return code. Bound Google upload, preparation, inference and cleanup independently. The locked GenAI SDK does not propagate a file-level abort signal to the browser uploader’s binary request, so bind the upload-phase signal through its client-level fetch override.

Chrome freezes page tasks and can discard the entire page when backgrounded. Browser Background Fetch cannot send the authenticated cross-origin requests that these providers require because Chromium blocks requests that need CORS preflight. Use a service worker message event with waitUntil for prepared work, with IndexedDB checkpoints at every part and a per-job Web Lock to coordinate reopened pages and other workers. Persist the request marker before the provider call and the transcript afterwards so a lost response does not cause an automatic duplicate request. A service worker can outlive a frozen page, while mobile OS suspension and service worker lifetime limits still apply. The provider preflight uses an authenticated GET against the selected provider’s model catalog. These metadata endpoints send no audio or prompt and run no inference. Browser CORS preflight against all three endpoints accepted the production origin and the provider’s authentication header. Reuse a recent result for concurrent jobs and abort checks on provider or key changes. HTTP 403 and 429 confirm the service answered, but model-catalog permissions and rate limits can differ from transcription permissions and limits, so warn and keep transcription available in those cases. The browser and FFmpeg repairs on 19 November 2026 load a worker on its first reserved job and replace the failed instance on retry. Keep the prepared segments and provider responses as one checkpoint keyed by effective audio and model settings so pause or upload errors do not resend completed chunks. FFmpeg can produce playable but incomplete output from a truncated source, so check exit status and demuxer diagnostics, and await temporary-file deletion. Measure the mono signal within each attempted track's transcode to skip digital silence without an extra decode for ordinary inputs. Reconcile matching words in the overlap with timestamp tolerance, retaining unpaired words because timestamps alone cannot prove a duplicate. Commit the IndexedDB replacement in one transaction after audio exists. Clipboard and storage failures require graceful browser-side fallback. The provider documentation specifies the direct-upload limits. [Groq](https://console.groq.com/docs/speech-to-text), [OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text).

On 19 November 2026, Playwright tests of `4b5b004` with synthetic media and intercepted provider responses reproduced jobs stranded when an FFmpeg worker is acquired before pool initialization or after both loads fail. Single-file pause loses its Resume state and repeats completed uploads when restarted. A denied microphone request deletes the previous IndexedDB draft because deletion precedes permission, and duplicate basenames silently overwrite ZIP entries. Native `ffprobe` confirmed that a silent first track masked later audio, damaged files yielded playable partial output, and Google duration splitting produced two approximately 953-second chunks from 1,900 seconds. Timestamp-midpoint ownership can drop or duplicate the same word when chunk estimates disagree, even with complete annotations. For compatibility checks, distinguish Windows WebKit from Safari hardware and verify transport separately from interception: its Playwright route reported zero file bytes for a known nonempty multipart upload that reached a loopback receiver intact. Chrome and Firefox recovered fake-microphone drafts. Chrome also converted this build's WAV fixture without cross-origin isolation. Mobile layout checks used browser emulation.

Hetzner deployment (2026-10-04): Level 1 hosting supports FTPS on port 21 without requiring SSH shell access. Use `FTP_TLS` with a verified SSL context and call `prot_p()` to encrypt data transfers as well as login. The main account sees `/public_html/transcribe`; the dedicated additional account starts inside `public_html`, so its correct deployment target is `/transcribe`. Confirm the target by comparing its `index.html` bytes with the live HTTPS response. Upload files under temporary names, rename each into place, and publish `index.html` last; keep old assets and existing server files. Browser FFmpeg also needs Apache COOP/COEP headers in the production build, since Vite's development headers do not configure the hosted server. Sources: [Hetzner FTP access](https://docs.hetzner.com/managed/administration-on-konsoleh/access-details/ftp-sftp/), [Python FTP TLS](https://docs.python.org/3/library/ftplib.html#ftplib.FTP_TLS).

Model catalog refresh (2026-10-04): OpenAI recommends `gpt-transcribe` for ordinary file transcription and `gpt-6-astra` for maximum text-model capability, with `gpt-6.1-sol` and `gpt-6-luna` providing balanced and budget alternatives. GPT-6 supports Chat Completions for this app's text-only transformation requests, so no endpoint or SDK migration is needed; omit `temperature` because reasoning-enabled GPT-6 requests reject sampling parameters. OpenAI transcription requests should use the default JSON response rather than Whisper-specific `verbose_json`; the queue only consumes `text`. Groq's generally available production choices remain `whisper-large-v3` for transcription accuracy and `openai/gpt-oss-120b` for text quality. Catalog order supplies defaults without persisting them as explicit choices; `getStoredModel` preserves valid saved choices and falls back for missing or obsolete values. Sources: [OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-6 migration](https://developers.openai.com/api/docs/guides/latest-model), [OpenAI models](https://developers.openai.com/api/docs/models), [Groq models](https://console.groq.com/docs/models), [Groq transcription](https://console.groq.com/docs/speech-to-text).

Google provider integration (2026-10-04): `gemini-3.5-transcribe` uses the Gemini Interactions API with an audio Files API URI, rather than an OpenAI-compatible transcription endpoint. The official GenAI JavaScript SDK accepts browser `File`/`Blob` uploads and derives `output_text` from the response steps. Wait for uploaded files to become ACTIVE, delete them in `finally` on success or failure, and report cleanup failures without discarding the transcript; Google expires files after 48 hours. Set `store: false` for stateless interactions. Verbatim transcription is the default and allows one hour per request (30 minutes with diarization or word timestamps); enforce duration independently of byte size, leave a margin for MP3 frame boundaries, and retain overlap for stitching. Snapshot provider settings per job so changing providers cannot bypass the limits used during splitting. Gemini 3.8 Flash and 3.5 Flash-Lite support text transformations with a separate system instruction. Sources: [transcription](https://ai.google.dev/gemini-api/docs/transcribe), [Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview), [Files API](https://ai.google.dev/gemini-api/docs/files), [models](https://ai.google.dev/gemini-api/docs/models).

Live transcript formatting (2026-10-04): Capture provider annotations during the initial request and keep normalized cues separately from plain text. Gemini 3.5 Transcribe combines `mode: {type: "verbatim", diarization_mode: "speaker", timestamp_granularities: ["word"]}` and returns `word_info` annotations in model-output text; requesting these features reduces its audio limit to 30 minutes, so use a 1790-second split ceiling. Groq Whisper and OpenAI `whisper-1` use `verbose_json` with word/segment granularities; OpenAI ordinary transcribe models do not expose those timestamps, while `gpt-4o-transcribe-diarize` requires `diarized_json` and `chunking_strategy: "auto"`. OpenAI SDK 7 provides the corresponding request/response types. Track each chunk's absolute offset and ownership interval to remove overlapping word cues once; use contiguous cuts for segment-only diarization, and namespace speaker labels by audio part because independent requests cannot establish identical voices. Reject incomplete annotation sets as a formatting source instead of dropping speech. Store cues with recent transcripts, but evict older entries or omit annotations from an oversized cached entry when localStorage fills. Display/export switches operate on retained data and never call a provider. Sources: [Google transcription](https://ai.google.dev/gemini-api/docs/transcribe), [Groq transcription](https://console.groq.com/docs/speech-to-text), [OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text).
